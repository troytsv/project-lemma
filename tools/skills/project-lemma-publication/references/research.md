# Research and manuscript checks

For a new investigation run `python <skill>/scripts/problem.py --repo <checkout> new <slug> --title "<title>"`. Repeating the same slug returns its directory. Reconcile that title and the next number with current main before publishing. Keep formal/, certificates/, verification/, results/ and research/ with the investigation when they have content. Start with the installed [manuscript](../assets/manuscript.tex) and [record](../assets/publication.md). Reuse existing files for an ongoing investigation.

| Question | Evidence to obtain |
| --- | --- |
| Is the mathematics correct? | Write a claim with explicit quantifiers. Check degenerate cases, strict endpoints, converse directions and every reduction. Try counterexamples and alternative arguments. Separate discovery code from an independent exact checker. Preserve failures and corrected derivations. |
| What has been formally verified? | Map each claim to a declaration, expand its predicates, inspect the domain, realizability, hypotheses and both extremal directions. Document interpretive steps left to prose. Record toolchain, library commits, trusted assumptions and actual output. |
| Was it known? | Search the original conjecture, citations in both directions, theses, preprints, databases and equivalent formulations. Test whether a stronger theorem implies it. Credit old constructions. Keep dated queries, pages, unavailable sources and conditional priority language. |
| Has it received independent peer review? | Identify who examined which version and what they concluded. Record automated or same-family AI review as such. External acknowledgment, a public listing and a DOI do not establish peer review. |

**Clean formal replay.** Prefer Lean 4 when practical. Inspect the pinned toolchain and manifest, Lake targets, exact audit filenames and permitted axioms. Build project sources into an empty build directory in a clean checkout. Reuse verified upstream artifacts if necessary and record this explicitly. For Problem 001 the working commands are in its `formal/VERIFICATION.md`: fetch the documented Mathlib cache, `lake --wfail build`, then `lake env lean -DwarningAsError=true` on both audits. Inspect transitive `#print axioms` output or programmatically enforce a justified allowlist. Search source for `sorry`, `admit`, `axiom`, unsafe proof hooks and native decision shortcuts; inspect matches in context. Record any genuinely impractical formalization and narrow the public claim accordingly.

**Independent computation.** Check input hashes, block or object sizes, label ranges, duplicates, coverage and counterexamples directly with exact arithmetic. Exercise invalid inputs. When a proof is computational, rerun the full proof-producing calculation or independent verifier and identify its trust assumptions. For 001 two optional upstream records enable an extra regression; count actual executions and skips. Its 39 historical rows and ten certified examples answer different questions.

**Prepare the paper.** Use the author name and independent-researcher affiliation only while accurate. The personally funded resources and commercial subscription statement is the default unless circumstances change. Obtain factual competing-interest and contribution statements for each investigation. Give sources for constructions and prior bounds; do not infer human discovery from commissioning the project. Add the date, version, theorem contracts, reproducibility and data availability links. Confirm every citation, URL, PDF page and reference; compile in isolation from the exact source archive. Remove template fields. Recheck licenses, upstream credits and historical grants. The current repository uses MIT for original code and CC BY 4.0 for original manuscripts and documentation.

**Preflight.** Inspect the staged file list and reachable public history for secrets, personal paths/contacts, unrelated data, incompatible rights, untracked dependencies and private communications; inspect PDF metadata and text too. Some earlier releases already contain abbreviated historical bylines. Preserve attribution history and qualify it in current disclosures. Retain the evidence and blockers in PUBLICATION.md. Feasible verification work belongs in Prepare even if publication is not authorized.
